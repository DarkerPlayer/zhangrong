# 人物与独立衣柜工作台设计

## 目标

将当前“人物和衣服烘焙在一张图中”的造型目录升级为人物、服装适配版本、背景和人设语料相互独立的本地衣柜工作台。运行时不接入图像 API；新服装仍通过 Codex 内置 ImageGen 按现有流程生成高质量合身立绘，然后随应用本地打包。

## 核心决策

- 人物拥有稳定 `characterId`；显示名可在本机改名，不改变素材 ID 或历史存档。
- 服装作为逻辑资产独立编目，记录发型、上衣、下装、连衣裙、外套、内衣、袜类、鞋履和配饰等部件。
- 视觉成品仍是人物专属的完整透明 PNG + `rig.json`。这是服装对某人物的高质量“适配版本”，而不是运行时粗糙拉伸。
- 现有 27 套造型作为首批适配版本保留，旧 `lookId` 继续可用。
- “全部不穿”是一个安全语义：15 位人物均切换到各自独立生成、透明底的白色比基尼基础适配版本，不生成裸露中间状态。

## 数据模型

### Character

`{ id, defaultName, age, aliases, defaultLookId, lookIds }`。本机状态使用 `characterProfiles[id].displayName` 保存改名结果。

### OutfitVariant

`{ id, characterId, lookId, name, description, slots, asset, rig, status }`。`slots` 描述这张合身成品中的发型和服装部件，供筛选、复用和后续 ImageGen 生成单使用。

### CharacterCorpus

每个人物保存自己的 `{ id, title, text, enabled, createdAt }`。启用的当前人物语料会经长度和数量上限校验后进入本地聊天提示；不伪装为历史消息或 system 角色。

### Background

`{ id, name, kind, theme }`。首版提供本地 CSS 背景主题，它们始终渲染在透明人物之后，不改变人物或服装选择。

## 交互

- 导航栏“衣橱”打开独立全屏工作台，不再是 520px 侧栏。
- 左侧是人物列表与改名，中间是带可切换背景的全身动态预览，右侧是“套装 / 部件 / 语料 / 背景”。
- 选择人物时优先保留该人物上次使用的适配版本；首次使用则选默认造型。
- 部件视图会呈现当前适配版本的完整分解信息，并能筛选具有相同部件类型的已有版本。
- 人物改名、当前造型、背景和角色语料都在本机持久化。

## ImageGen 资产流程

后续用户上传服装图时，提取非品牌专属的版型、材质、配色和细节，写入可复用服装元数据；以目标人物当前立绘为 identity-preserve 编辑对象，生成正面全身透明图，校准 rig，记录提示词和来源。一件服装可按需添加多个人物适配版本。

## 兼容与验证

- 从 `muyu-state-v1` 读取旧数据时，保留聊天、收藏、造型、已移除造型和原有语料。
- 旧全局语料迁移到恢复时当前人物，不丢失。
- 服务端校验人物名与语料的类型、条数和长度，避免把本地存储中的任意结构直接变成提示词。
- 自动测试覆盖状态迁移、改名、语料隔离、提示词注入、人物/服装映射、背景独立和独立衣柜页的主要交互。
