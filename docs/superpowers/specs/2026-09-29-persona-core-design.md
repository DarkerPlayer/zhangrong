# 独立女友人格本体设计

## 目标

把应用中的“女友身份”从立绘、Live2D 模型和服装中完全拆出。语料人格是唯一的身份本体；视觉模型只是可随时更换的外观皮肤。切换外观不得改变姓名、性格、亲密等级、声音偏好、聊天记录或记忆，切换人格也不得改变当前外观、服装、背景或动作能力。

首版内置三位完整的成年女友人格：温柔姐姐型、俏皮年下型和冷面女上司型。每位人格都支持轻甜、成熟暧昧、成人三档语言强度，并拥有完全独立的聊天、收藏、记忆和用户自定义语料。

## 产品原则

- `Persona` 是女友本人，是聊天界面、称呼、历史、语料、关系和声音偏好的唯一身份来源。
- `Appearance` 只负责立绘、服装、背景、动画和动作能力，不提供聊天姓名或性格。
- `Persona` 和 `Appearance` 之间不保存默认绑定、固定绑定或反向引用。
- 同一人格可以使用任意现有外观；同一外观也可以被任意人格使用。
- 换衣、换模型和切换图片场景都不等于换女友。
- 所有内置人格均明确为 25 岁以上成年人。“姐姐型”和“年下型”描述相处风格，不表示现实亲属关系。
- 成人档仅用于成年人之间自愿的虚拟互动，不改变应用对现实身份、现实能力和模型能力的如实说明。

## 范围

### 首版包含

- 三个内置人格本体及其结构化语料。
- 独立的人格选择与管理界面。
- 每人格独立的三档亲密等级。
- 每人格独立的聊天记录、收藏、称呼、偏好记忆、自定义语料和声音偏好。
- 内置人格复制为可编辑自定义人格。
- 本地模型与离线回退共同使用同一人格定义。
- 现有本地状态的无损迁移。
- 外观与人格的双轴选择及完整自动化回归测试。

### 首版不包含

- 云端同步、账号系统或跨设备同步。
- 向量数据库、Embedding 或大规模文档检索。
- 在线人格商店。
- JSON 人格包导入导出；数据结构为后续能力预留版本字段，但首版不暴露文件导入入口。
- 让视觉模型名称、服装名称或图片元数据自动决定人格。

## 核心领域模型

### PersonaDefinition

内置的只读人格模板。每个模板位于独立模块中，并由统一目录导出。

```js
{
  schemaVersion: 1,
  id: "boss-girlfriend",
  name: "林岚",
  age: 31,
  archetype: "冷面女上司",
  relationship: "girlfriend",
  identity: {
    selfDescription: "...",
    relationshipStyle: "...",
    boundaries: ["..."]
  },
  speechStyle: {
    rhythm: "短句、干练、克制",
    vocabulary: ["过来", "听话", "做得不错"],
    teasingStyle: "带掌控感的轻微调侃",
    forbiddenPatterns: ["幼态表达", "突然变成甜妹口吻"]
  },
  corpora: {
    greeting: ["..."],
    daily: ["..."],
    affection: {
      sweet: ["..."],
      mature: ["..."],
      adult: ["..."]
    },
    teasing: {
      sweet: ["..."],
      mature: ["..."],
      adult: ["..."]
    },
    seduction: {
      sweet: ["..."],
      mature: ["..."],
      adult: ["..."]
    },
    comfort: ["..."],
    jealousy: ["..."],
    praise: ["..."],
    goodnight: ["..."],
    action: {
      pat: ["..."],
      wave: ["..."],
      outfit: ["..."]
    },
    fallback: ["..."]
  }
}
```

模板必须满足以下约束：

- `id` 全局稳定且唯一；改名不得改变 `id`。
- `age` 不低于 25。
- `relationship` 固定为 `girlfriend`。
- 所有必要语料分类非空。
- `sweet`、`mature`、`adult` 三档必须分别提供内容，不能让多个档位引用同一数组。
- 模板不得包含 `lookId`、`characterId`、`modelId`、服装 ID 或外观资源路径。

### PersonaProfile

本机可变的人格实例。内置人格以模板 ID 为基础，自定义人格由内置人格复制产生。

```js
{
  id: "persona-instance-id",
  templateId: "boss-girlfriend",
  displayName: "林岚",
  age: 31,
  intimacyLevel: "mature",
  adultAcknowledged: false,
  voiceProfileId: null,
  disabledCorpusIds: [],
  customCorpora: [],
  createdAt: 0,
  updatedAt: 0
}
```

- `displayName`、年龄、语言补充和声音可以在自定义副本上修改。
- 内置实例允许修改显示名、亲密等级、声音、启停项和追加自定义语料；其原始模板内容保持只读。
- 删除自定义人格前必须至少保留一个可用人格。
- 成人档首次启用时设置 `adultAcknowledged: true`；该确认只保存在本机。

### PersonaThread

每个人格实例拥有独立线程。

```js
{
  messages: [],
  savedMessages: [],
  memories: {
    userName: "",
    preferences: [],
    relationshipFacts: []
  }
}
```

- `messages` 最多保留最近 200 条，与现有上限一致。
- `savedMessages` 独立保留，不随滚动历史删除。
- `memories` 只从当前人格收到的用户消息中提取，不读取其他人格线程。
- 首版继续采用确定性本地规则提取称呼和偏好；不引入模型自动写长期记忆。
- 切换人格后，请求历史必须立即改为目标人格线程，不能携带切换前人格的最后一条消息。

### AppearanceState

现有 `lookId`、`avatarMode`、`scene`、`backgroundId`、`removedLookIds` 和衣橱数据继续描述视觉状态。视觉目录内部可暂时保留历史字段名 `characterId` 以避免一次性重写资产，但该字段在聊天域中仅表示“同一视觉模特的造型分组”，不得用于推导人格。

应用层必须停止使用 `getCharacterForLook(lookId)` 计算聊天身份。聊天姓名统一来自 `activePersonaId` 对应的 `PersonaProfile`。

## 持久化状态

状态升级为显式 `schemaVersion: 2`：

```js
{
  schemaVersion: 2,
  activePersonaId: "persona-instance-id",
  personas: {
    "persona-instance-id": { /* PersonaProfile */ }
  },
  personaThreads: {
    "persona-instance-id": { /* PersonaThread */ }
  },
  lookId: "ruby-velvet",
  avatarMode: "live2d",
  scene: "home",
  backgroundId: "moon-room",
  settings: { /* 非人格专属的应用设置 */ }
}
```

`activePersonaId` 与 `lookId` 是两个平级且互不影响的状态。选择人格的 reducer 不得写视觉字段；选择外观的 reducer 不得写人格字段。

## 内置人格内容

### 温柔姐姐型

- 年龄 29 岁。
- 说话舒缓、成熟、会照顾情绪，但不过度说教。
- 调侃方式是看穿用户的小心思后温柔点破。
- 轻甜档偏照顾和依恋；成熟档增加主动靠近和反问；成人档保持成熟、主动和清晰自愿。

### 俏皮年下型

- 年龄 25 岁。
- 机灵、黏人、节奏轻快，喜欢故意逗用户再哄回来。
- “年下”只表示成年女友的年龄感和相处风格，不是妹妹或其他现实亲属。
- 轻甜档偏撒娇；成熟档增加大胆双关和主动挑战；成人档仍保持成年、自愿和非幼态表达。

### 冷面女上司型

- 年龄 31 岁。
- 公开语气干练克制，私下体现反差式亲密和掌控感。
- 调侃多用简短命令、评价和留白，但不得把现实工作权力用于强迫。
- 轻甜档是克制关心；成熟档增加掌控感和奖励式表达；成人档保持双方自愿并避免胁迫语义。

每个人格至少提供：

- `greeting`、`daily`、`comfort`、`jealousy`、`praise`、`goodnight`、`fallback` 各 4 条。
- `affection`、`teasing`、`seduction` 每个强度各 4 条。
- 常用动作 `pat`、`wave`、`outfit` 各 3 条。

模板中的内容允许 `{userName}` 和 `{personaName}` 两个占位符；其他占位符一律在校验时拒绝。

## 对话数据流

### 前端请求

前端从 `activePersonaId` 解析当前人格，并只读取对应的 `PersonaThread`。`/api/chat` 请求包含：

- 当前用户消息。
- 当前人格线程最近 24 条消息。
- 经过合并的当前人格快照。
- 当前人格记忆。
- 当前 `lookId`、场景和画面模式。
- 模型与 provider 设置。

请求不再发送由外观推导出的 `characterName` 或 `characterCorpus`。

### 服务端校验

服务端新增人格快照规范化：

- 验证人格 ID、名称、成年年龄、模板 ID和亲密等级。
- 限制身份说明、语言规则、数组条数、单条长度和总字符数。
- 只接受允许的语料分类与占位符。
- 忽略未知字段。
- 拒绝人格中出现外观绑定字段。
- 保证历史只包含 `user` 和 `assistant` 角色。

### 意图选择

新增确定性 `detectDialogueIntent(message)`，至少识别问候、日常、示爱、调侃、安慰、吃醋、夸奖、晚安、亲密表达、动作、换装和普通回退。它用于：

- 从当前人格中选择本次相关的 2 至 4 条参考语料。
- 在离线模式选择当前人格自己的候选回复。
- 避免把整个语料包塞进 4096 token 上下文。

选择函数应结合最近三条当前人格回复避免逐字重复，并保持相同输入下可测试的确定性。

### 模型提示组装

模型消息顺序为：

1. 应用的硬能力、现实边界和输出格式要求。
2. 当前人格身份、关系和语言规则。
3. 当前亲密等级及与本次意图相关的少量语料。
4. 当前人格记忆。
5. 独立的视觉上下文。
6. 当前人格规范化后的历史。
7. 本次用户消息。

视觉上下文可以描述服装、场景和动作能力，但不得把视觉目录中的人物名作为自称。提示中明确说明：“当前外观只是画面，不改变你的身份。”

用户自定义语料作为受限参考材料插入，不能新增 system/tool 角色，也不能覆盖能力边界、现实身份说明或输出格式要求。

### 离线回复

离线引擎必须接收同一份规范化人格快照和亲密等级：

- 问候、示爱、调侃、安慰、吃醋、夸奖、晚安、亲密表达和普通回退均从当前人格语料中选择。
- 摸头、挥手和换装等确定性动作使用当前人格的 `action` 语料。
- 能力限制继续由应用的确定性规则回答，但允许使用当前人格的称呼和句式包裹，不得谎称支持不存在的能力。
- Ollama 不可用时回退后仍能明显辨认三种人格。

## UI 与交互

### 女友页

新增独立“女友”入口，不放在衣橱内部。页面包括：

- 人格列表与当前人格标记。
- 姓名、年龄、类型和简介。
- 轻甜、成熟暧昧、成人三档选择。
- 当前人格专属语料的查看、添加、启停和删除。
- 当前人格的声音选择。
- “复制为自定义人格”操作。

切换人格后，主界面的姓名、字幕归属、聊天历史、收藏和导出文件名立即切换；外观画面不刷新、不换装。

### 衣橱页

衣橱只展示外观模特、套装、部件、背景和动作能力：

- 移除“当前角色名称”和“角色语料”编辑区。
- 将视觉列表中的名字标注为“外观模特”或“形象”，不把它们展示为当前聊天身份。
- 换外观后主界面仍显示当前人格名称。

### 成人档确认

首次为某个人格选择成人档时显示一次本机确认，说明所有内置人格均为成年人且内容仅为虚拟互动。取消则维持原档位；确认后只记录到该人格的 `adultAcknowledged`。

## 声音归属

声音库文件仍保存在现有本机目录。`PersonaProfile.voiceProfileId` 保存该人格选择的声音；未设置时使用声音库当前默认项。切换人格时应用选择该人格声音，切换外观不得改变声音。

## 迁移

从当前 `muyu-state-v1` 恢复时执行一次性迁移：

1. 保留所有视觉状态、设置、自定义媒体和已移除造型。
2. 若存在全局 `messages`、`savedMessages`、`corpora` 或用户称呼，创建名为“张容”的自定义人格并将这些数据迁入其独立线程和语料。
3. 对 `characterProfiles` 中具有自定义显示名或语料的每个条目，创建一个独立自定义人格；只迁移名称和语料，不保存原 `characterId` 与新人格的运行时绑定。
4. 如果没有任何旧人格数据，创建三个内置人格实例并默认选择温柔姐姐型。
5. 无论旧数据是否存在，三个内置人格实例均保持可用；旧数据迁移人格之外的内置人格使用空白独立线程。
6. 迁移后写入 `schemaVersion: 2`，重复恢复不得再次复制人格或消息。

旧字段可在一个兼容版本中继续读取，但新写入状态以 `personas` 和 `personaThreads` 为准。

## 错误处理与降级

- 当前人格缺失或损坏时回退到温柔姐姐型，不改变当前外观。
- 人格线程缺失时创建空线程。
- 某个语料分类缺失时使用该人格 `fallback`，不得借用其他人格语料。
- 成人档未确认时服务端规范化为 `mature`。
- 自定义语料超限时在保存处提示，并在服务端再次拒绝或截断到明确上限。
- 本地模型失败时使用当前人格离线回复；不得回退成共享的“张容”通用话术。
- 声音不存在时回退到声音库默认项，不修改人格或外观选择。

## 测试与验收

### 领域测试

- 三个内置人格通过 schema 校验，ID 唯一、年龄合规、所有必需分类和三档语料非空。
- 人格定义不包含任何外观绑定字段或资源路径。
- 自定义副本拥有新实例 ID，修改后不改变内置模板。
- 非法占位符、未知亲密等级、未成年年龄和超长内容被拒绝。

### 状态与迁移测试

- 选择新外观后 `activePersonaId`、人格配置和线程完全不变。
- 切换人格后 `lookId`、场景、背景和服装完全不变。
- 三个人格的消息、收藏、称呼和偏好互不出现。
- v1 全局聊天迁移到“张容”人格且不丢消息；旧角色语料迁移后没有运行时外观绑定。
- 多次恢复 v2 状态不会重复迁移。

### 对话测试

- 模型提示只出现当前人格身份和当前人格历史。
- 视觉模特名不会被用作聊天自称。
- 三种人格对同一问候、安慰和调侃输入产生可辨认的不同离线回复。
- 同一人格三个亲密等级选择不同语料集合。
- 用户自定义语料不能增加 system/tool 消息或移除能力限制。
- 模型失败后的回退仍保持当前人格。

### API 与 UI 测试

- API 接受合法人格快照并拒绝错误类型、超限数据和外观绑定字段。
- 人格切换请求只携带目标人格的最近 24 条消息。
- 女友页可以切换人格、修改亲密等级、复制人格和管理专属语料。
- 成人档未确认时不能生效。
- 衣橱页不再编辑人格，换装后主界面姓名和聊天不变。
- 导出回忆使用当前人格名称且只导出当前人格线程。

## 完成标准

- 用户可以在三个内置人格间切换，并清楚感受到稳定且不同的语言特征。
- 任意人格可以配任意外观，两个选择互不改写。
- 三档亲密程度在本地模型和离线模式中都生效。
- 人格之间不存在历史、收藏、记忆、声音或自定义语料串线。
- 旧数据迁移后仍可访问，现有衣橱、动作、语音、桌宠和聊天能力没有回归。
- `npm test` 与 `npm run build` 均通过。
