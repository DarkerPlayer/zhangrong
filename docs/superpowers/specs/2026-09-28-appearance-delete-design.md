# 可恢复删除人物造型设计

## 用户目标

衣橱中可以移除单套人物造型，并在需要时恢复。移除后，主衣橱和桌宠衣橱都不再显示这套造型；如果它当前正在使用，应用应切换到仍保留的造型；聊天中的换装指令不能重新选中已移除造型。

## 方案选择

1. **本地可恢复移除（采用）**：在现有应用状态中保存已移除造型的 ID，通过“已移除”视图恢复。原始素材和目录定义保留。
2. **永久删除目录及素材**：直接删除静态目录项和文件，无法在应用中恢复，也会影响打包素材和既有数据迁移。
3. **仅从当前列表临时隐藏**：改动较小，但刷新后状态消失，且聊天入口仍能选中隐藏造型。

方案 1 保留用户可逆操作，同时能够让两处衣橱与聊天换装共用同一状态。

## 架构与数据流

- `LOOKS` 继续作为只读基础目录。应用状态增加 `removedLookIds`，复用当前本地持久化；恢复状态时只保留目录中存在的 ID，并去重。
- 主衣橱和桌宠衣橱从相同状态派生可用列表与已移除列表。摘要数量只统计可用造型。两个视图都提供移除与恢复入口；卡片的选择操作与移除操作是独立按钮。
- 移除当前正在使用的造型时，优先切换到默认且未移除的动态造型，再选择任一未移除造型；若没有剩余动态造型，则使用不可移除的 Haru 原始造型。
- `/api/chat` 请求携带已移除造型 ID。服务端验证 ID 后，在解析聊天换装别名时排除已移除项。客户端用始终最新的移除状态检查 `lookAction`，拦截与移除操作并发完成的旧响应。
- 移除不删除图片、模型文件或静态目录项。恢复只需从“已移除”视图还原 ID。

## 交互与错误处理

- 每张可用造型卡提供清晰的“移除造型”操作；已移除视图中的卡片提供“恢复”。
- 误触风险通过可恢复机制处理，不额外增加确认弹窗。
- 若本地状态无法保存，沿用现有存储错误提示，当前会话中的状态仍按 React 状态处理。
- 若移除期间聊天请求返回该造型，客户端不切换到它，并继续展示聊天回复。

## 范围与验证

本次仅支持移除或恢复单套造型，不删除整个人物、素材文件或 Haru 原始造型。实现后构建应用，检查主衣橱、桌宠衣橱、状态恢复、当前造型回退和聊天换装过滤；不新增或运行测试套件。

## 预期改动文件

- `src/state.mjs`：保存并校验 `removedLookIds`，保证恢复状态不会选中已移除造型。
- `server/looks.mjs`、`src/looks.mjs`：按可用 ID 筛选造型、生成统计并解析可用命令别名。
- `server/dialogue.mjs`、`server/index.mjs`：将已移除 ID 贯穿聊天输入和换装判定。
- `src/App.jsx`、`src/PetShell.jsx`：共享移除/恢复状态、回退选择并提供两处衣橱入口。
- `src/WardrobeFilters.jsx`：提供可用与已移除视图及动态数量。
- `src/wardrobe.css`：卡片操作与已移除视图样式。
