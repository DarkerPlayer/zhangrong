# 1.16 本地生成验收

日期：2026-10-02。设备：Apple M1 Pro，16 GB 统一内存。使用更新后的 `release/母狗张容.app`，没有调用云端图像接口。

## 安装与自动验证

- 独立 Python 3.12.13、MFLUX 0.20.0、MLX 0.32.2。
- 模型：`Runpod/FLUX.2-klein-4B-mflux-4bit`，固定修订 `7ee1b3aa8178a1240050490072196a57da2bf2a9`，下载文件验证 LFS SHA256。
- 模型及独立环境合计约 5.9 GB 磁盘空间（`du` 显示约 5.5 GiB）。
- 全部 284 项 Node 测试通过，11 项 Python 测试通过，生产构建通过。
- 独立审查发现并修复了多实例覆盖目录，以及导入期间关闭面板后界面未更新的问题。

## 首张真实推理

从桌面衣柜进入本地生成，通过原生文件选择框上传内置 `wuduohui-plaid-agent/character.png`，填写藏蓝连衣裙和黑色尖头高跟鞋的描述。

- 任务：`d2f216b4-6dc9-442f-92ac-0a17eb56f5eb`。
- 尺寸：512 × 768，1 张参考图，4 步。
- 创建到预览：58.544 秒，包含排队、权重加载、推理、透明处理和五官定位。
- MLX 报告的分配峰值：5,016,417,990 B，约 5.02 GB。
- macOS 报告的生成进程 physical footprint 历史峰值：5,754,507,296 B，约 5.75 GB。
- 生成进程 max RSS：1,313,488,896 B。RSS 没有包含全部 Metal 统一内存，因此不能代替 physical footprint，也不能与 MLX 峰值相加。
- 完成后生成进程退出，没有继续持有图像权重。

返回陪伴页后，四个 Electron 进程当时的 physical footprint 合计约 574 MB；这一快照不包含其他应用、系统缓存、独立语音或聊天进程，也不代表所有场景的固定占用。

原生输入、参考图上传、生成进度、离开面板后的预览保存、右侧滚动条手动拖动和五官校准控件已实际检查。人物、头顶、手、裙装和双鞋完整。首轮发现浅色边缘污染，已在窄轮廓带去除背景混色，并在深色背景下目视确认；合成软边测试的颜色误差减少超过 50%，白色衣服内部保持不变。

重新启动桌面应用后预览成功恢复；通过“加入衣橱并使用”登记，模特列表与套装列表立即出现新人物，自动选择并由原有动态渲染器显示。当前女友仍为“张容”。

## 高跟鞋适配与最终恢复

在新人物的“部件”页点击黑色尖头高跟鞋的“为当前造型本地适配”，使用默认中文描述。服务自动提供已登记的人物图和库存鞋款图作为两张参考。

- 任务：`18fc5bdf-0006-450d-8bca-9c49fc61839a`。
- 尺寸：512 × 768，2 张参考图，4 步。
- 创建到预览：70.632 秒。
- MLX 分配峰值：5,152,009,934 B，约 5.15 GB。
- max RSS：1,533,263,872 B。步骤 3 的一次系统快照显示 physical footprint 5.035 GB、当时历史峰值 5.704 GB；此快照不是该任务的全程最终峰值。
- 生成进程完成后退出。

本轮发现低透明度边缘的颜色噪声被放大，修复后软边近饱和异常像素由 13 降至 0，并新增回归测试。透明图与深色背景下的预览均检查过。

通过界面登记后，库存显示高跟鞋“已穿上”；恢复原鞋、再次穿上均成功。正常退出并重开后，新人物仍被选中，衣柜仍显示“本地生成 · 黑色尖头高跟鞋”，两条生成记录均为已登记。没有覆写内置人物或其他造型的鞋履适配。

已部署版本：1.16.0。首次安装移植到新 Mac 仍需要 Python、uv 和 Swift 编译工具；当前设备已安装完整环境，不影响离线生成。
