# 项目接入与验收

这些路径对应本技能整理时的仓库结构；开始时确认实际代码，若实现已演进，以当前接口为准。不要凭旧示例硬编码角色 ID、坐标、时长、测试数量或绝对机器路径。

## 资源与目录

| 职责 | 当前入口 |
| --- | --- |
| 权威角色/造型目录 | `server/looks.mjs`；`src/looks.mjs` 复用 |
| 主体图与校准 | `public/looks/<look-id>/character.png`、`rig.json` |
| 动作帧 | `public/looks/<look-id>/actions/` |
| 角色来源与生成记录 | 该造型的 `provenance.json`、`docs/wardrobe-new-models.json` |
| 可复用单品 | `public/wardrobe/items/`、`server/wardrobe.mjs` |
| 画面运行效果 | `src/GlamPet.jsx` 与 `src/motion/` |
| 面部坐标辅助 | `scripts/face-landmarks.swift` |

现有完成案例是 `fancha` / `fancha-rose-office`。复用其结构与验收方法，新角色使用自己的 ID、文件夹和数据。保持旧角色、动作、归档/隐藏记录、女友人设、语音和历史数据不被本次接入覆盖。

## 每张新图重新校准

1. 检查尺寸、真实 alpha、非透明区域和人物位置。主立绘与派生帧保持一致的画布约定，不能只因为尺寸相同就假设眼睛、嘴和脚的位置也相同。
2. 在 macOS 可用只读辅助命令提取当前图的面部坐标：

   ```sh
   swift scripts/face-landmarks.swift --full-body public/looks/<look-id>/character.png
   ```

   将 `<look-id>` 换成实际目录后运行。输出使用左上角为原点的归一化坐标；检测结果是初值，须检查是否确为主体脸，尤其侧脸、低头或画面有其他人时。识别失败则依据实际图人工校准，不套旧人物坐标。
3. 更新头部范围、颈部、双眼、嘴、肩部和 bounds；按实际肤色、眼睑、唇色调整颜色样本。左右眼应按图像坐标对应渲染器期望，避免反转。
4. 检查运行时眨眼、说话、待机摆动和面部稳定处理。若刚性单层立绘的手臂变形破坏细节，可按该图结构收紧 `armMobility`；不要将某角色的 0 值强加给所有角色。
5. 对 authored 动作帧同时检查动作表情保护、落地点和混合采样，详见 [动作抽离](actions.md)。

角色在原图里像、在应用里不像，通常需要先判断是素材、坐标还是覆盖效果导致；不要同时无依据地改变三者。

## 记录可追踪来源

沿用现有 provenance，至少记录：用户参考分工、可长期访问的参考位置、生成提示词、生成原文件、采用版本与最终路径、尺寸/透明度、校准来源、被替换版本的备份、已做的验证。

用户临时剪贴板附件若需要后续复用，可按任务需要复制到项目参考资源位置，并在记录里关联原始路径；不要只保存一个会被系统清理的临时路径。原始生成图不覆盖，项目资源使用明确的最终版本。大文件按仓库现有约定存放，不把缓存和应用打包副本一起提交。

## 按改动选择验证

| 改动 | 最低有意义的检查 |
| --- | --- |
| 只有技能/说明 | frontmatter、链接、路径、使用场景试读；不启动生成或重打包 |
| 静态图/rig | 关键局部、真实 alpha、当前图校准、运行时眨眼/口型与缩放 |
| 动作 | 阶段和终止测试、触发/打断、表情保护、落地点、运行时完整播放 |
| 衣橱数据/服务/UI | 分类、组合与恢复、导入/持久化、来源与跨角色隔离、预览及相关服务/UI 测试 |
| 公共渲染/状态逻辑 | 扩展到相关资源释放、旧角色动作、状态回归；必要时全量测试 |

本项目 JavaScript 测试使用 `node --test`，生产构建用 `npm run build`；执行前检查 Node 是否满足当前 Vite 版本。不要使用不兼容的旧 Node，或在同一绿灯结果后反复全量测试。工具链不可用时如实报告范围，保留已经完成的资源。

局部对照包括用户强调的眼神、眉眼、甲色、腰腹曲线及衣料下肚脐；全身对照包括比例、配饰、人物边缘和实际显示尺寸。只要求本次有参考或需求的视角，不为单张正面任务额外杜撰侧背面交付。

## 需要交付到桌面应用时

先确认用户实际运行的是开发服务还是打包应用。仅更新工作区文件或浏览器不等于桌面已经更新。

- 沿用当前项目打包方式；涉及 Electron、原生依赖或运行时布局时使用正常 `npm run build:desktop` 流程。
- 已确定仅前端资源与少量纯 JS 服务文件有变化、且当前应用支持该更新方式时，可以先备份，再同步构建产物和确切的已改服务文件。核对资源哈希，按已有授权重启并查看实际应用。
- 不将整个工作区盲目覆盖进安装包，不写死本机用户目录。记录更新和备份位置；未实际更新桌面时直说只完成了工作区修改。

实现细节的历史说明可参考 [模型与衣橱工作流](../../../../docs/wardrobe-model-workflow.md)；当前请求及当前代码比历史记录优先。
