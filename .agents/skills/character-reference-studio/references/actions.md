# 动作抽离

## 从参考图拆出动作

把用户指定的动作描述成可见运动：起始姿态、目光与头部方向、手的位置、与头发/服饰的接触、嘴型、主要动作、收势。不要从一张图额外推断完整剧情、其他人物或台词。

以项目现有 `spit` 为例，参考的是低头、手拢头发、嘴唇姿态和短暂的唾液细节。它单独作为一次动作，静态默认立绘仍使用用户选定的表情。这是动作制作的示例，不是其他角色的默认行为。

## 资源与时序

1. 为动作设置稳定 ID。资源放到 `public/looks/<look-id>/actions/`，让造型目录引用它；不要把动作永久烘焙进默认立绘。
2. 简单动作可拆为 prepare / release / recover，复杂动作按需要增加阶段。`spit` 已有 550 / 350 / 700 ms 的一次播放示例；新动作时长由动作节奏决定。
3. 以认可的主立绘为身份、服装和配饰依据派生帧。保持画布、人物尺度、画风、甲色、发型、手表、耳环和覆盖范围一致，检查手指、手发接触与嘴部细节。
4. 检查每帧真实 alpha 和脚底边界。逐帧记录落地点，基于当前主立绘校准待机基准，不复制示例角色的坐标。
5. 检查交叉渐变时基础图和动作图各自的定位。只给动作网格加位移可能使基础图一起跳动；当前渲染器用 `uBaseUvOffset` 补偿基础采样，让待机图保持原世界位置。

本项目动作帧是整身图。独立复用的是动作定义、触发和制作方法；另一套服装、另一个角色的动作图需要相应适配，不能直接沿用原角色帧。

## 表情与运行状态

- 指定表情由动作画面承担时，使用 manifest 的 `preserveExpression` 能力，检查眨眼、音频口型、红晕、面部稳定覆盖和网格变形是否覆盖了作者画好的表情。
- 一次动作完成后回待机。重复触发、打断、切换造型、取消待机都要清理 active/pending 状态；异步加载返回后不能把已切走的造型换回来。
- 只为拥有资源的造型开放对应动作。缺失时使用真实的不可用反馈，不拿无关动作冒充。
- 只有请求涉及对话触发时才扩展文本路由。区分明确动作命令与否定、回忆、描述性提及，避免“不要做某动作”反而播放。
- 适配衣橱组合后，当前 `resolveWardrobeAppearance` 无条件关闭旧整身动作（`actions: null`），本地 fit 导入也未保存组合动作字段。用户要求换装后保留动作时，需为新组合制作匹配帧，并扩展组合动作的保存、解析、加载与资源校验后才能启用；只添加 PNG 不会自动生效。按完整组合关联动作，验证恢复某部位后的组合也使用自己的帧。

## 接入位置与检查

| 职责 | 当前文件 |
| --- | --- |
| 造型与动作资源引用 | `server/looks.mjs`，前端经 `src/looks.mjs` 引用 |
| 声明、阶段与姿态 | `src/motion/MotionManifest.mjs`、`src/motion/adapters/GlamMotionAdapter.mjs` |
| 缺失资源回退 | `src/motion/MotionFallback.mjs` |
| 图像混合、表情、落地点 | `src/GlamPet.jsx` |
| 资源释放 | `src/glam-action-resources.mjs` |
| 操作入口 | `src/LookActionMenu.jsx`、`src/App.jsx`、`src/PetShell.jsx` |
| 明确文本意图 | `server/dialogue.mjs` |

按修改范围运行 `tests/spit-action.test.mjs`、`tests/spit-ui.test.mjs`、`tests/glam-motion.test.mjs`、`tests/glam-action-resources.test.mjs` 等相关测试；名称是现有示例，新动作需验证对应行为，不能以旧测试通过代替新动作验收。

实际预览开始、主要动作、收势和回待机，尤其检查表情被覆盖、脚底跳动、淡入残影、动作中切装、重入和切换后资源释放。只检查静止截图无法验证动作完成。
